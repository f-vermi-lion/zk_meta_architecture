== 8.1 正本と派生成果物

[cols="2,2,2,2",options="header"]
|===
| 対象
| 正本
| 管理対象入力
| 派生成果物

| 文書
| ソースリポジトリのAsciiDoc、Antora component設定、navigation
| -
| Antoraが生成したHTML

| C4図
| Structurizr DSL
| レイアウト付きJSON workspace
| 生成SVG

| サイト
| サイト用リポジトリのplaybook、UI、workflow
| -
| `build/site`、Pages artifact、公開サイト

| 自動化
| GitHub Actions workflowと検査ツール
| -
| Actions log、検査結果、build artifact
|===

派生成果物を直接編集して正本化しない。
管理対象入力は正本ではないが、後続生成に必要な情報を保持するためリポジトリで管理する。
ただし、生成SVGはAntoraが読むassetとしてリポジトリ管理する。
詳しい更新単位は xref:architecture-documentation-publishing-platform/c4-structurizr-diagram-management/08-concepts.adoc[図管理の横断的コンセプト]で扱う。

== 8.2 全体と部分

親文書はシステム全体の境界と子文書間の関係を示す。
子文書は、それぞれ独立したarc42文書として領域固有の規則、構成、実行時動作、品質、リスクを記述する。

親子関係はディレクトリのネストとAntora ``xref``で表す。
関連する子文書同士も、処理や成果物を受け渡す箇所から直接リンクする。

== 8.3 領域をまたぐ変更

一つの変更が複数領域へ影響するときは、関係する正本と派生成果物を同じ変更単位で扱う。
代表例は次のとおりである。

* 文書構造の変更とnavigation / xrefの更新
* 図モデルの変更とJSON workspace / 生成SVG / 説明本文の更新
* 日英ページの追加と対応ページ / `:lang:` / 検査設定の更新
* content sourceの追加とplaybook / 権限 / 横断検査 / 公開workflowの更新

== 8.4 未決定事項の扱い

決定済みの標準経路と、検討中の拡張やリスク対策を分ける。
未決定事項の内容と影響は対応する子文書の11章で管理する。
具体的な着手候補は必要に応じて``inbox.md``へ送り、
決定後に``decisions/``、必要なら``decision_records/``、関連する親子文書へ反映する。
