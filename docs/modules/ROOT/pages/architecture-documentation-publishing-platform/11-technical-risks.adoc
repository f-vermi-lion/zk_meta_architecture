== 11.1 リスクの所在

[cols="2,3,2",options="header"]
|===
| リスク
| 全体への影響
| 詳細

| 文書構造の重複・参照切れ
| 全体と部分で異なる規則が正本化され、閲覧者が詳細へ辿れない。
| xref:architecture-documentation-publishing-platform/document-structure-and-authoring-rules/11-technical-risks.adoc[文書構造・執筆規約]

| 図モデルとレイアウトの不整合
| 古いJSON workspaceやSVGが公開され、説明と図が一致しない。
| xref:architecture-documentation-publishing-platform/c4-structurizr-diagram-management/11-technical-risks.adoc[図生成・管理]

| private文書の公開・site buildの不安定化
| 非公開情報の漏洩、または公開サイトの更新停止につながる。
| xref:architecture-documentation-publishing-platform/antora-site-publishing/11-technical-risks.adoc[サイト集約・公開]

| 日英版の同期ずれ
| 対応ページ欠落や古い補助版が公開される。
| xref:architecture-documentation-publishing-platform/bilingual-document-operation-and-validation/11-technical-risks.adoc[日英文書運用・検査]

| cross-repository権限・失敗検出
| 自動公開が起動しない、過剰な権限を持つ、失敗に気づけない。
| xref:architecture-documentation-publishing-platform/cross-repository-publishing-orchestration/11-technical-risks.adoc[公開オーケストレーション]
|===

== 11.2 未決定事項

|===
| ID
| 未決定事項
| 主な担当

| UC-1
| private repositoryの文書をpublic GitHub Pagesへ出してよいか。

| docToolchainのAntora連携をどこまで採用するか。

| 公開オーケストレーション

| UC-4
| サイト再生成失敗をどう通知し、誰がどう再実行するか。
| 公開オーケストレーション

| UC-5

| 日英文書運用・サイト集約

| 日英ページの内容差分や更新鮮度を検査するか。
| 日英文書運用

| UC-9
| view key変更時にJSON workspaceのレイアウトをどう移行するか。
| 図生成・管理

未決定事項の内容と影響は対応する子文書で管理し、
具体的な着手候補だけを必要に応じて`inbox.md`で追跡する。
