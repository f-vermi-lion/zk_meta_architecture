== 10.1 品質シナリオ

[cols="2,3,3",options="header"]
|===
| シナリオ
| 応答
| 受け入れ条件

| 子文書を追加する
| 親directory配下へ独立したpage groupを追加し、親indexとnavigationから接続する。
| 親から一回のリンクで子indexへ移動でき、子indexから親へ戻れる。

| 文書の表示順を変える
| navigationの順序だけを変更する。
| 文書directoryと既存resource IDを変更せずに済む。

| 長い文書を分割する
| 親に全体像を残し、独立した詳細を子文書へ移す。
| 同じ詳細が親子双方で正本化されず、関連情報がxrefで接続される。

| pull request前に確認する
| ローカル内容をcontent sourceにしてAntora buildし、生成HTMLを目視する。
| 新規ページ、navigation、表、コードブロック、xrefが生成サイト上で確認できる。

| AIが文書を編集する
| 意味のある章または子文書だけを読み、関係する正本を更新する。
| 無関係な領域を変更せず、親子の境界と既存決定を維持できる。
|===

== 10.2 完了条件

文書構造の変更は、少なくとも次を満たしたとき完了とする。

* 全ページに必須メタデータがある。
* 親、子、関連文書のxrefが存在する。
* navigationに公開すべきページが登録されている。
* Antora buildで参照解決エラーがない。
* 生成サイトで対象ページの見た目を確認している。
