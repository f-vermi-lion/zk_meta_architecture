== 10.2 全体品質シナリオ

=== 10.2.1 文書と図を変更する

文書作成者が文書または図を変更したとき、
正本、必要な派生成果物、参照を同じ変更単位でレビューでき、
pull request前に生成サイト上の表示を確認できる。

=== 10.2.2 複数リポジトリを公開する

ソースリポジトリの`main`が更新されたとき、
source側検査、site側横断検査、Antora build、Pages deployの結果を追跡できる。
どこかで失敗した場合は古い公開結果と新しい正本を区別できる。

=== 10.2.3 詳細を探す

閲覧者または保守者が親文書を読んだとき、
担当する子文書へ一回のリンクで移動できる。
子文書からは親文書と直接関係する他の子文書へ戻れる。

== 10.3 最低条件

本体文書の作成を始める最低条件は次のとおりである。

* 文書配置、命名、メタデータ、相互参照の規則が決まっている。
* 図の正本、レイアウト、生成、配置の規則が決まっている。
* サイト用リポジトリの責務と最小build / deploy経路がある。
* 日英文書の対応方針と最低限の検査仕様がある。
* 自動化の未実装部分と未決定の権限・運用が明示されている。
