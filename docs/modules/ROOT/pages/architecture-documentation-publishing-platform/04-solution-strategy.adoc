== 4.1 基本戦略

* 文書と図の正本は、それらが説明するソースコードに近いソースリポジトリへ置く。
* 文書はarc42とAsciiDocで構成し、Antora標準構成で管理する。
* C4図はStructurizr DSLをモデル正本とし、公開用SVGを生成する。
* 専用サイトリポジトリが複数のcontent sourcesを集約し、Antoraでサイトを生成する。
* 英語正本と日本語補助版は同一component内の別moduleとして管理する。
* GitHub Actionsが検査、生成、集約、GitHub Pages公開を接続する。

== 4.3 段階的な実装

最小構成ではpublicなcontent source、手動build、手動Pages deployから始める。
その後、共通検査、図生成、`repository_dispatch`、複数リポジトリ、
必要な権限と失敗時運用を段階的に有効化する。

未実装の標準フローを、初期構成で既に動作しているものとして扱わない。

== 4.4 既存ツールの優先

独自実装は、既存ツールでは表せない検査、リポジトリ間の接続、運用補助に限定する。
docToolchainは補助候補として残すが、現時点の公開サイト生成の中心はAntoraとする。
