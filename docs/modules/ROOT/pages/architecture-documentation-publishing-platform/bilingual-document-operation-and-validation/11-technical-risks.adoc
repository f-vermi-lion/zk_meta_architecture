== 11.1 内容と更新鮮度

初期checkerはpageの存在と`:lang:`だけを検査する。
日本語補助版が古い、翻訳内容が欠けている、
正本と意味が異なるといった問題は検出できない。

内容差分や更新鮮度を検査対象にするかは未決定である。
自動化する前に、何を同等とみなし、どの差を失敗にできるかを決める必要がある。

== 11.2 publish workflow未統合

checker本体とtestが存在しても、
publish workflowから呼ばなければ公開gateとして機能しない。

content sources取得後のworktreeとcontent rootをどう列挙するかは未決定である。
接続が実装されるまでは、checker実装済みと公開時検査済みを区別する。

== 11.3 言語切り替え導線

moduleを分けただけでは、閲覧者が対応pageを見つけられない可能性がある。
page上部、navigation、UI selector、生成linkのどれを標準にするかは未決定である。

最小案として手動xrefを置くことはできるが、
link欠落を初期checkerは検出しない。

== 11.4 草稿の未対応が残る

草稿で片方だけの更新を許すと、
対応版の作成が長期間忘れられる可能性がある。

公開gateで両版を要求し、
草稿中の未対応はpull request、task、または別の明示的な管理単位で追跡する。

== 11.5 正本と補助版の誤解

UIやpage内に役割が表示されないと、
閲覧者が日本語補助版を最新の正本と誤認する可能性がある。

言語導線を決める際に、
正本・補助版の表示と更新日をどこへ示すかも合わせて決める。
