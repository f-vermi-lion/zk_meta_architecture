== 9.2 判断経緯を残した決定記録

判断経緯は、リポジトリ内の`decision_records/`に置く。

decision recordは、現在有効な決定そのものではなく、なぜその決定にしたかを説明する履歴である。

[cols="1,3,2",options="header"]
|===
| 決定記録ファイル
| 主な内容
| 関連する現在有効な決定

| `decision_records/architecture_document_format_revision.md`
| arc42本文をMarkdown前提からAsciiDocとGitHub Pages前提へ改めた理由。
| `architecture_documents.md`, `architecture_document_publication.md`

| `decision_records/architecture_document_layout_revision.md`
| arc42文書ディレクトリの連番をやめ、章番号を章ファイルへ移した理由。
| `architecture_documents.md`

| `decision_records/architecture_documentation_platform_from_docs.md`
| docs草稿からアーキテクチャ文書公開基盤の方針へ進めた理由。
| `architecture_documentation_platform.md`, `architecture_document_publication.md`

| `decision_records/architecture_document_languages.md`
| 造智機巧のアーキテクチャ文書を英語正本・日本語補助版にした理由。
| `architecture_document_languages.md`

| `decision_records/architecture_document_language_antora_modules.md`
| 日英版をAntora moduleで分ける理由。
| `architecture_document_languages.md`
|===

== 9.3 未決定事項との関係

未決定事項は、3章の未決定事項と11章の技術的リスクで管理する。

未決定事項が解決したら、以下のいずれかに反映する。

* 現在有効な方針として`decisions/`へ反映する。
* 判断経緯を残す価値が高い場合は`decision_records/`を追加する。
* arc42本文の関連章を更新する。
* 必要なら`inbox.md`または`tasks.md`から該当項目を削除・完了にする。

この章では、未決定事項を決定済みのように扱わない。
