== 1.1 目的

リポジトリ間公開オーケストレーションは、
文書正本を持つ複数のソースリポジトリと、
統合サイトを生成するサイト用リポジトリを接続する。

source側で正本と派生成果物を確認してからsite側処理を起動し、
横断検査、Antora build、GitHub Pages deployを順序どおり実行する。
失敗時には後続公開を止め、原因と再実行経路を残す。

== 1.2 対象

* pull request、`main` push、`workflow_dispatch`、`repository_dispatch`
* source側検査とsite側検査の境界
* サイト再生成依頼
* build / deployの停止条件
* log、artifact、公開結果の追跡
* 手動再実行
* cross-repository権限とtoken / secretの未決定事項

各検査や生成処理の内部仕様は担当子文書を正本とする。

== 1.3 品質目標

[cols="1,3",options="header"]
|===
| 品質目標
| 説明

| 順序が明確
| source側検査に成功した変更だけがsite側公開へ進む。

| 失敗を局所化できる
| 文書、図、日英、site build、deployのどこで失敗したか分かる。

| 再実行できる
| 自動イベントが失敗しても、同じsite処理を手動起動できる。

| 権限を限定できる
| repository間の起動とPages deployに必要な権限だけを与える。

| 状態を誤認しない
| 正本更新、site build成功、Pages公開成功を別々の状態として追跡できる。
|===
