== 9.2 現時点の主要決定要約

対象システムは、「各リポジトリ内の文書正本」と「専用サイトリポジトリのAntora集約・公開設定」からなる文書公開基盤と定義する。

ソースリポジトリ側は「文書を書く場所」、専用サイトリポジトリ側は「集めて公開する場所」とする。

専用サイトリポジトリの標準名は`zouchikikou-docs-site`とし、この決定後すぐ作成する。

各ソースリポジトリの`main`更新後は、`zouchikikou-docs-site`へ`repository_dispatch`で再生成を依頼する。`zouchikikou-docs-site`の公開workflowは`repository_dispatch`と手動の`workflow_dispatch`を受け付ける。

初回のGitHub Pages deployは、`zouchikikou-docs-site`の`.github/workflows/publish.yml`を`workflow_dispatch`で手動実行する。workflowはAntora build結果の`build/site`を`actions/upload-pages-artifact@v4`でPages artifactとしてuploadし、`actions/deploy-pages@v4`でGitHub Pagesへdeployする。Antora playbookは`.nojekyll`を生成物に含める。`repository_dispatch`、cross-repository token / secret、private repositoryの取り込み、共通検査ツール実行は別段階で有効化する。

2026-05-23時点の初回公開URLは、https://f-vermi-lion.github.io/zouchikikou-docs-site/meta-architecture/architecture-documentation-publishing-platform/index.html である。

日本語版・英語版は同一component内のAntora moduleで分ける。英語正本は`ROOT` module、日本語補助版は`ja` moduleに置き、対応するページはmodule配下の相対パスとファイル名を揃える。

公開時と版確定時のCIでは、英語正本`docs/modules/ROOT/pages/**/*.adoc`と日本語補助版`docs/modules/ja/pages/**/*.adoc`の対応ページ欠落、および`:lang:`不一致を失敗扱いにする。`meta_architecture`自体は日本語運用のため、この日英必須検査の対象外にする。

日英対応検査の標準コマンドは、専用サイトリポジトリ内の`tools/check-language-pairs`とする。このコマンドは、公開workflowがcontent sourcesを取得した後、Antora buildの前に実行する。

図の標準生成経路は、Structurizr DSL/JSONからStructurizrの`export -format svg`で直接SVGを生成する方式にする。PlantUML / C4-PlantUML経由は標準経路にしない。モデル変更の出発点は`workspace.dsl`とし、手動レイアウトを再現する場合は`workspace.json`をexport入力として管理する。

標準配置の具体例は、8.2で管理する。

== 9.4 未決定事項との関係

未決定事項は、11.8の未決定事項一覧と11章の技術的リスクで管理する。

未決定事項が解決したら、以下のいずれかに反映する。

* 現在有効な方針として`decisions/`へ反映する。
* 判断経緯を残す価値が高い場合は`decision_records/`を追加する。
* arc42本文の関連章を更新する。
* 必要なら`inbox.md`または`tasks.md`から該当項目を削除・完了にする。

この章では、未決定事項を決定済みのように扱わない。
