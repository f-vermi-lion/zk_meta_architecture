== 1.1 目的

アーキテクチャ文書公開基盤は、文書と図の正本を各ソースリポジトリに置いたまま、
複数リポジトリの文書を一つのサイトへ集約し、GitHub Pagesで閲覧可能にする。

文書作成者が本文、図、相互参照へ集中できるようにし、
検査、集約、サイト生成、公開は可能な範囲で自動化する。

== 1.3 品質目標

[cols="1,3",options="header"]
|===
| 品質目標
| 説明

| 内容へ集中できる
| 文書作成者が、公開基盤固有の手作業を毎回行わずに文書と図を更新できる。

| 正本が明確である
| 文書本文、図モデル、設定、派生成果物の役割を区別できる。

| 変更を確認できる
| pull request前に文書、図、生成サイトを確認でき、公開後も結果とlogを追跡できる。

| 全体と詳細を辿れる
| 親文書から子文書へ、子文書から親文書や関連文書へ移動できる。

| 既存ツールを活用する
| arc42、AsciiDoc、Antora、Structurizr、GitHub Actions、GitHub Pagesを優先して使う。
|===

== 1.4 ステークホルダー

[cols="1,3",options="header"]
|===
| 役割
| 期待

| F
| 日本語で内容を確認でき、文書内容以外の操作が過度な負担にならない。

| Codex / ChatGPT
| コードと文書を同時に参照でき、意味のある単位に分かれた文書を編集・レビューできる。

| リポジトリ貢献者
| 配置規則と検査結果から、変更すべき正本と完了条件を判断できる。

| 文書サイト閲覧者
| 直接リンク、ナビゲーション、親子文書間のリンクから必要な情報へ辿れる。
|===
