== 3.1 対象システム

アーキテクチャ文書公開基盤は、複数のソースリポジトリに配置された
arc42形式のAsciiDoc文書、図定義、関連設定を収集・検査・変換し、
GitHub Pages上の静的ドキュメントサイトとして公開する仕組みである。

対象には次を含む。

* 文書構造、配置、メタデータ、相互参照の規約
* C4／Structurizr図の正本、レイアウト、生成、検査の規約とworkflow
* Antora playbook、サイトbuild、GitHub Pages deploy
* 日英文書の配置規則と対応検査
* ソースリポジトリとサイト用リポジトリをつなぐworkflow

対象には、GitHub、GitHub Actions、GitHub Pages、Antora、Structurizrなどの製品本体、
各ソースリポジトリで開発するアプリケーション本体、
AIツール本体、翻訳品質の完全保証を含めない。

== 3.2 業務コンテキスト

|===
| 外部要素
| 基盤への入力
| 基盤からの出力

| 文書作成者

| 文書サイト閲覧者
| Web閲覧要求
| GitHub Pages上の文書、図、ナビゲーション
|===

== 3.3 技術コンテキスト

全体の技術的な流れは次のとおりである。

. ソースリポジトリで文書、図、設定を変更する。
. source側workflowが、担当する正本と派生成果物を検査する。
. ``main``更新後、サイト用リポジトリへ再生成を依頼する。
. サイト用リポジトリがcontent sourcesを取得し、横断検査とAntora buildを行う。
. GitHub Actionsが生成サイトをGitHub Pagesへdeployする。
. 閲覧者がHTTPSで公開サイトを読む。

外部技術インターフェースは、Git、GitHub Actions workflow、
Antora content source / resource ID、Structurizr workspace / export、
GitHub Pages artifactである。各インターフェースの詳細は対応する子文書で扱う。

== 3.4 親子文書の境界

この親文書は、対象システム全体の目的、境界、子文書間の責務、全体フローを正本として扱う。
配置規則、コマンド、workflowの手順、検査仕様などの詳細は子文書を正本とし、
親文書には要約とリンクだけを置く。
