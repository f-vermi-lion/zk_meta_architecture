| 用語
| 説明

| アーキテクチャ文書公開基盤
| 複数のソースリポジトリにある文書と図を集約・検査・変換し、GitHub Pagesへ公開する仕組み。

| 親文書
| 対象システム全体の目的、境界、部分間の関係、全体フローを示すarc42文書。

| 子文書
| 親文書の構成要素を一つの対象として、領域固有の構成、動作、規則、品質、リスクを示すarc42文書。

| ソースリポジトリ
| コードと、その対象に属する文書・図の正本、Antora設定、source側workflowを置くリポジトリ。

| サイト用リポジトリ
| Antora playbook、UI、共通検査、公開workflowを持つリポジトリ。標準名は``zouchikikou-docs-site``。

| 正本
| 後続の編集、検査、生成の基準となる一次成果物。

| 派生成果物
| 正本と設定から生成されるHTML、SVG、artifact、logなど。

| content source
| Antora playbookが文書を取得するGitリポジトリ、branch、tag、start pathの指定。

| Antora component
| ``antora.yml``で識別される文書群の単位。

| Antora module
| component内の文書区分。この基盤では英語正本に``ROOT``、日本語補助版に``ja``を使う。

| Structurizr DSL
| C4モデルとviewをテキストで定義するDSL。この基盤ではC4図モデルの正本。

| Structurizr JSON workspace
| 手動レイアウトを含むSVG export入力。モデル正本ではない。

| `repository_dispatch`
| ソースリポジトリから別リポジトリのworkflowへ再生成を依頼するイベント。

| `workflow_dispatch`
| GitHub Actions workflowを手動実行するイベント。

| 日英対応検査
| 英語正本と日本語補助版のページ欠落、および``:lang:``不一致を検出する検査。
|===
