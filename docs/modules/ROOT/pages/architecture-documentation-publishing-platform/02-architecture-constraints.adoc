== 2.1 技術的制約

* 文書体系はarc42を基本とし、本文はAsciiDocで記述する。
* 文書の配置とサイト生成はAntoraのcomponent、module、page、partial、assetの構造に従う。
* C4図のモデル正本にはStructurizr DSLを使い、公開用の標準形式はSVGとする。
* リポジトリと自動化にはGit / GitHub / GitHub Actionsを使う。
* 公開先はGitHub Pages、サイト生成の中心はAntoraとする。
* 外部製品の機能は設定と公開済みインターフェースを通じて利用し、製品本体はこの基盤に含めない。

各領域固有の制約は、次の子文書で扱う。

* xref:architecture-documentation-publishing-platform/document-structure-and-authoring-rules/02-architecture-constraints.adoc[文書構造・執筆規約の制約]
* xref:architecture-documentation-publishing-platform/c4-structurizr-diagram-management/02-architecture-constraints.adoc[C4／Structurizr図生成・管理基盤の制約]
* xref:architecture-documentation-publishing-platform/antora-site-publishing/02-architecture-constraints.adoc[Antoraサイト集約・公開基盤の制約]
* xref:architecture-documentation-publishing-platform/bilingual-document-operation-and-validation/02-architecture-constraints.adoc[日英文書運用・検査の制約]
* xref:architecture-documentation-publishing-platform/cross-repository-publishing-orchestration/02-architecture-constraints.adoc[公開オーケストレーションの制約]

== 2.2 組織的制約

* 主な製作者はFとAIであり、継続的な有料サービスや複雑な手作業への依存を抑える。
* Fは日本語話者であるため、``meta_architecture``自体は日本語で記述する。
* 文書と実装はGit差分としてレビューでき、既存のソースリポジトリ運用に乗せられることを優先する。

== 2.3 慣例

* 決定済みの規則、検討中事項、派生成果物を混同しない。
* 全体像は親文書、各領域の詳細は子文書に置き、同じ詳細を複数文書で正本化しない。
* 親子文書と関連子文書はAntoraの``xref``で接続する。
