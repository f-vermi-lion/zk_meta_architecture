== 1.1 目的

文書構造・執筆規約は、アーキテクチャ文書の正本を
コードと同じソースリポジトリで一貫して管理できるようにする。

文書を人間とAIの双方が扱いやすい単位へ分け、
Antora上の識別子とリンクを安定させ、
全体文書から部分文書へ辿れる状態を維持する。

== 1.2 対象

この文書は次を扱う。

* arc42文書の階層と章ファイル
* Antora content root、component、module、page、partial、assetの配置
* 文書・ディレクトリ・章ファイルの命名
* ページメタデータ
* `xref`と`include`による接続・再利用
* 文書を作成、分割、更新、確認する手順

図モデルと生成手順、日英対応検査、サイト公開workflowの内部は扱わず、
対応する子文書へ接続する。

== 1.3 品質目標

[cols="1,3",options="header"]
|===
| 品質目標
| 説明

| 編集単位が明確
| 章、節、または独立した子文書として、意味のある大きさに分かれている。

| 識別子が安定
| 表示順や一時的な名前を変えても、文書ディレクトリとresource IDが不要に変わらない。

| 正本が一つ
| 同じ規則や詳細を親文書と子文書の両方で正本化しない。

| 関係を辿れる
| 親子文書、関連文書、再利用断片が明示的なリンクまたはincludeで接続される。

| 草稿を確認できる
| pull request前に未pushのローカル内容を使ってAntora buildし、生成ページを確認できる。
|===
